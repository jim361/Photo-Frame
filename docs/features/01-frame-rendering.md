# 01. 프레임 렌더링 엔진

## 목적

필름·디지털·폰 사진 위에 프레임과 촬영 정보를 합성해 공유할 결과물을 만든다. 사용자는 스타일 하나를 고르고 정보를 채우면 되고, 레이아웃·타이포·비율은 도구가 책임진다.

## 현재 동작

`render(src, opts, info): canvas` — 원본 크기 기준으로 새 캔버스에 합성한다. 미리보기와 내보내기가 같은 함수를 공유하고, `info.collect`일 때만 미리보기 경계용 요소 상자를 수집한다.

**공통 텍스트 규칙**
- `infoRows(o)`: 한 줄 또는 두 줄에 놓을 요소 키를 정하고 빈 항목을 자동 생략한다.
- `rowLayout()`: 구분자를 넣지 않고 각 요소의 실제 폭과 간격으로 한 행을 배치해 개별 드래그 상자와 렌더 위치를 일치시킨다.
- `trackedText`: `ctx.letterSpacing` 지원 시 사용, 미지원 브라우저는 글자 단위 수동 렌더 폴백
- 프레임 번호(`01A`) 표기는 롤 번호·시작 프레임 필드와 함께 제거됨 (2026-07, 사용자 결정)

새 4종은 `bottom`/`top`의 정보 행·날짜·서명 배치 경로를 함께 사용한다. 별도 렌더 엔진은 없으며 `frameDims()`도 같은 여백 수치를 사용한다. 매트 계열의 여백 그립은 `borderScale`을 조절하고 균등 매트·키라인에는 독립 띠 핸들을 만들지 않는다.

**인스탁스 규격 변형**
- 세 규격은 사진 비율을 유지하고 여백 모양만 적용한다. 사진을 자르거나 늘이지 않으며 출력 카드의 가로세로 비율·인쇄 크기를 고정하지 않는다.
- 실제 필름/사진 영역은 미니 54×86/46×62mm, 스퀘어 72×86/62×62mm, 와이드 108×86/99×62mm다. 근거: [미니 공식 사양](https://asset.fujifilm.com/www/ph/files/2020-12/5cc03b7f067001e7045d7c6d0f3070df/instax_mini_datasheet.pdf), [스퀘어 공식 안내](https://www.instax.com/squareformat/en/), [와이드 공식 카탈로그](https://asset.fujifilm.com/www/ca/files/2020-12/1008a588df16e2c2e91ad1393c498bb2/instax_300_catalogue.pdf)
- 스퀘어·와이드는 양옆 여백을 균등 배분하고 위에도 같은 여백을 둔다는 앱의 해석으로 위 표의 기본값을 정한다. 미니는 기존 결과 호환을 위해 원래 수치를 유지한다. 표의 기본 여백에 `borderScale`, 정보 영역에 `bandScale`을 적용하고 글자 기본 크기도 규격의 정보 여백에 맞춘다.
- `instaxMetrics()`의 여백 값을 크기 계산과 기존 인스탁스 렌더 분기에서 함께 사용한다. 규격마다 별도 엔진을 만들지 않으며 미리보기·썸네일·넘침 검사·내보내기가 같은 배치를 쓴다.
- 미니의 저장 키는 기존 `instax` 그대로다. 스퀘어·와이드는 각각 독립 스타일 키와 세로/가로 프로파일을 사용하며 설정·프로젝트·레이아웃/디자인 프리셋에 저장한다. 가로 글씨 방향 선택은 미니의 가로 사진에만 표시한다.

**스타일 선택·색상**
- 현재 사진과 장별 정보를 작은 로컬 Canvas에서 같은 `render()`로 그려 스타일 버튼 10개에 표시한다. 사진·설정·글꼴/로고 로딩 상태가 바뀌면 갱신한다. 장비 팔레트의 값은 스타일을 바꿔도 변하지 않는다.
- 상단/하단/매트 계열/미니멀은 스타일별로 흰색 기본, 흰색·검정·아이보리 버튼, 네이티브 색상 선택기와 HEX(`#RGB` 또는 `#RRGGBB`)를 제공한다. 잘못된 HEX는 적용하지 않는다.
- 색상 조작은 기본으로 접힌 `여백 색` 패널을 열어 사용한다. 열림·닫힘 상태는 다른 접이식 패널과 함께 `frame.panels`에 기억하며, 필름·인스탁스에서는 패널을 숨긴다. 패널을 접어도 선택한 색상은 유지된다.
- 새 사용자 색의 정보·메모·날짜·텍스트 서명은 상대 휘도로 대비가 더 높은 검정/흰색을 고른다. 이미지 로고 자체의 색은 바꾸지 않는다.
- 기존 `tone:light/dark`는 원래 배경·정보·날짜·서명 색까지 `frameColors`/`legacyBandTones`로 이전한다. 사용자가 해당 스타일의 색을 직접 바꾸면 자동 대비로 전환한다. 필름의 색은 그대로다. 인스탁스 카드는 세로·가로 모두 순백색(`#ffffff`)으로 고정하며 화면의 화이트/블랙 테마와 관계없이 미리보기·썸네일·내보내기에서 같은 색을 쓴다.
- 비율 패딩의 새 기본은 프레임 색 따름이며 별도 색상 조작은 숨긴다. 기존 고정색은 설정·프로젝트·디자인 프리셋에서 그대로 복원·저장한다.

**안전장치**
- `safeScale(W,H,o)`: 스타일별 합성 결과 크기를 사전 계산해 브라우저 캔버스 한계(iOS 4096² 면적 / 그 외 변 16384·면적 1.2억px) 초과분만큼 소스를 축소. 축소 시 미리보기 토스트(장당 1회)와 내보내기 완료 메시지로 안내.
- EXIF 회전: `createImageBitmap(file, { imageOrientation: 'from-image' })`로 디코드 시 확정, 미지원 브라우저는 `<img>` 폴백.

`downscale(cv, longEdge)`: 내보내기 시 긴 변 기준 축소 (2048/1440/원본), `imageSmoothingQuality: 'high'`.

## 설계 결정

- **원본 해상도로 합성 후 마지막에 축소** — 텍스트·퍼포레이션이 축소 과정에서 자연스럽게 안티앨리어싱된다. 처음부터 작게 그리면 얇은 스트로크가 뭉개진다.
- **모든 수치를 사진 폭 W의 비율로** — 어떤 해상도의 사진이 와도 프레임 비율이 동일하다.
- **DOM 캔버스 사용 (OffscreenCanvas 아님)** — 현재 측정에서 워커·추가 빌드 구조가 필요할 병목이 확인되지 않아 가장 단순한 경로를 유지한다.
- SVG/CSS 합성이 아닌 Canvas인 이유: 결과물이 픽셀 이미지 파일이어야 하고, 미리보기=결과물 일치가 필요하다.

## 알려진 한계

- **색 관리 차이** — 이미지 디코딩과 Canvas 색 관리는 브라우저·OS에 의존한다. 임베디드 ICC가 항상 무시된다고 단정하지 않으며, 색이 중요한 파일은 sRGB 시험 내보내기를 권장한다.
- 긴 텍스트는 `fitSize()`가 가용 폭에 맞춰 자동 축소하지만 최소 55%까지만 — 그 이하로 필요한 극단적 입력은 잘릴 수 있다. 두 줄 레이아웃 권장.
- 캔버스 한계 검출이 UA 기반 휴리스틱 — 실측(프로브) 방식이 아니라 보수적 상수를 쓴다.
