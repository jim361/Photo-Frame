# 03. 필름 스트립 (선택/정렬/삭제/배치 대상)

## 목적

사진 묶음 작업의 중심 UI. 불러온 사진을 스트립에 나란히 놓고, 현재 미리볼 사진과 촬영 정보를 함께 바꿀 사진들을 구분해 선택한다. 스트립 순서가 곧 내보내기 순서다.

## 현재 동작

- 하단 흰 작업 바(`#strip`)에 높이 128px, 사진 비율에 따라 폭 102~144px인 칩을 표시한다. 상단 74px 사진 영역은 `object-fit: contain`으로 잘리지 않게 보이며, 하단에는 선택·삭제 조작 영역을 분리한다. 빈 상태에는 안내 문구가 나온다.
- **현재 사진**: 칩 본문을 클릭하거나 포커스한 뒤 Enter/Space를 누르면 `state.current`가 바뀐다. 현재 사진은 3px 검정 구조선으로 표시되고 미리보기와 촬영 정보 패널이 갱신된다.
- **배치 대상**: 칩 왼쪽 아래 48×48px 레이블 안의 체크박스로 여러 사진을 고른다. 선택 칩은 검정 현재 사진 테두리 바깥의 3px cobalt 선으로 표시되며, 체크 즉시 촬영 정보 범위가 `선택 N장`으로 바뀐다. 촬영 정보 패널의 `전체 선택` 버튼은 전부 선택/선택 해제를 전환한다.
- **정보 상태 표시**: 왼쪽 위 `E`는 EXIF 장별 정보가 있는 사진, `●`는 사용자가 입력값·표시 여부·전역 사용 상태 중 하나를 장별로 지정한 사진이다. 둘 다 있으면 `●`를 우선 표시한다.
- **삭제**: 오른쪽 아래에 항상 보이는 48×48px 빨간 × 버튼을 누르면 배열과 배치 선택에서 제거하고 해당 원본 디코드 객체를 바로 해제한다. 삭제 취소는 제공하지 않으며, PC의 원본 파일은 그대로라 필요하면 다시 추가할 수 있다. 내보내기 사전 검사·처리 중에는 대기 사진의 이미지가 해제되지 않도록 삭제를 잠근다.
- **정렬**: HTML5 Drag and Drop을 사용한다.
  - `dragover`에서 칩의 좌우 절반을 판정해 cobalt 세로선으로 삽입 위치를 표시한다.
  - `drop`에서 뽑힌 자리를 보정해 순서를 바꾸고, 보고 있던 사진과 배치 대상은 사진 객체 기준으로 그대로 유지한다.
- **대체 정렬**: 썸네일 아래 맨 하단의 작은 `←` / `→` 아이콘 버튼으로 현재 사진을 한 칸 옮긴다. 버튼은 기본 28×28px, 터치 포인터에서는 40×40px이며 한국어 접근성 이름과 툴팁을 제공한다. 사진이 없으면 버튼 행을 숨기고, 맨 앞·뒤에서는 해당 방향 버튼을 비활성화한다. 포커스한 사진 칩에서 `Shift+←/→`도 같은 동작을 한다.
- **작업 상태**: 사진은 썸네일에서, 현재 사진·선택 장수와 촬영 정보 적용 범위는 촬영 정보 패널에서 확인한다. 중복 상태 줄은 없으며 작업 중에도 상단 `＋ 사진 추가`가 항상 보인다.
- 스트립은 `role="list"`, 각 칩은 `role="listitem"`과 사진명 기반 레이블을 사용하고 현재 사진은 `aria-current`로 알린다. 체크박스와 삭제 버튼도 별도 접근성 이름을 갖는다. 목록을 다시 그려도 같은 사진의 칩·체크박스·삭제 버튼에 키보드 초점을 유지한다.

## 설계 결정

- **현재 사진과 배치 대상을 분리**한다. 현재 사진은 미리보기 대상이고, 체크된 사진은 촬영 정보 일괄 적용 대상이다.
- 배치 대상은 사진 객체를 담은 `Set`으로 보관한다. 인덱스가 아니라 객체를 사용하므로 정렬해도 선택 대상이 바뀌지 않는다.
- HTML5 DnD와 전체 재렌더(`innerHTML = ''`)를 유지한다. 현재 목표 장수에서는 의존성이나 DOM diff가 필요하지 않다.
- 스트립은 원본을 다시 디코드하지 않고 로드 직후 만든 긴 변 180px JPEG data URL을 사용한다. 출력은 원본 디코드 객체를 계속 써 품질과 배치를 바꾸지 않는다.

## 알려진 한계

- 터치 기기의 자유 드래그 정렬은 없고 한 칸 이동 버튼을 사용한다.
- 출력용 원본 디코드 객체는 모든 사진에 유지하므로 고해상도 사진을 많이 불러오면 메모리 부담이 남는다. 실제 고해상도 36장 메모리는 이번 변경에서 측정하지 않았다.
- 체크된 배치 대상은 촬영 정보·표시 여부와 `선택 N장 내보내기`에 사용한다. 내보내기는 체크 순서와 관계없이 스트립 번호를 유지한다. 선택 사진만 삭제하는 기능은 없다.
- 배치 선택은 작업 중 UI 상태라 프로젝트 파일에 저장하지 않는다.

## 개선 계획

- [x] 터치·키보드에서 현재 사진을 한 칸씩 옮기는 대체 조작

## 수용 기준

- [x] 드래그로 내보내기 순서를 바꿀 수 있다
- [x] 순서 변경 후에도 현재 사진과 배치 대상이 유지된다
- [x] 삭제 시 배치 대상과 원본 디코드 객체를 바로 정리하고 PC 원본 파일은 유지한다
- [x] 드롭 위치가 좌우 절반 기준으로 표시된다
- [x] 가로·세로 썸네일에서 사진 전체를 확인할 수 있다
- [x] 여러 사진을 촬영 정보 일괄 적용 대상으로 선택할 수 있다
- [x] EXIF 사진과 장별 수정 사진을 스트립에서 구분할 수 있다
- [x] 키보드로 현재 사진을 선택할 수 있다
- [x] 터치·키보드에서도 한 칸 이동 버튼으로 순서를 바꿀 수 있다
