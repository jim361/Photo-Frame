# 05. 프리셋 (장비·레이아웃·디자인)

## 목적

자주 쓰는 카메라/렌즈/필름·기타 값과 프레임별 배치를 저장해 두고 클릭 한 번으로 적용한다. 장비는 조합 단위가 아니라 **항목 단위 팔레트**로 관리하고 레이아웃은 스타일별 세로·가로 한 쌍으로 관리한다.

## 현재 동작

- **구조**: 카메라 / 렌즈 / 필름 세 행의 팔레트. 각 행은 저장된 값 칩 목록 + `＋` 버튼이며 너비가 부족하면 줄바꿈한다.
- **저장**: `＋` 클릭 → 해당 입력 필드의 현재 값을 그 열에 저장. 빈 값·중복은 토스트로 거절.
- **적용**: 칩 클릭 → 해당 입력 필드에만 값 반영 (`input` 이벤트 발생 → 자동 저장 + 미리보기 갱신). 다른 항목은 건드리지 않는다.
- **삭제**: 적용 버튼 옆의 독립된 48px × 버튼을 누르고 확인하면 삭제한다. 장비·레이아웃·로고 팔레트가 같은 버튼 구조를 사용하며, 두 동작 모두 키보드로 실행할 수 있다.
- **저장소**: `store` 래퍼로 localStorage `frame.gear` — `{ body: [], lens: [], film: [] }`. 접근 실패 시 메모리 폴백. 구버전 조합 프리셋(`frame.presets`)이 남아 있으면 첫 실행 때 값만 이전한다.
- **시드**: 배포본은 빈 팔레트로 시작하고 입력 예시도 특정 장비명을 사용하지 않는다. 예전 배포본이 자동 저장했던 Nikon·렌즈·필름 시드 묶음만 감지해 제거하며, 사용자가 추가한 다른 프리셋과 구버전 사용자 프리셋은 유지한다. 제거된 값이 필요하면 사용자가 현재 입력 옆 `＋`로 다시 저장할 수 있다.
- 팔레트 값은 datalist 자동완성 후보로도 쓰인다.
- 긴 값은 칩에서 말줄임(ellipsis) 처리, 전체 값은 툴팁으로 표시.
- **레이아웃 프리셋**: 현재 프레임 스타일의 세로·가로 프로파일 한 쌍을 이름 붙여 `frame.layouts`에 저장한다. 프리셋 목록은 현재 스타일에 속한 항목만 보여 주며, 적용해도 다른 프레임 스타일의 배치는 바꾸지 않는다. 적용 직전 프로파일은 줌바의 다단계 `배치 되돌리기` 기록에 추가된다. 스타일 필드가 없는 구버전 프리셋은 현재 스타일에서 계속 적용할 수 있다.
- **JSON 이동**: `프리셋 내보내기`는 장비 팔레트와 레이아웃 프리셋만 `photoframe-presets` v1 JSON으로 저장한다. 사진·현재 작업 설정·로고·글꼴은 포함하지 않는다. 연결한 저장 폴더가 있으면 그곳에 저장 완료로, 없으면 완료 여부를 알 수 없는 다운로드 요청으로 표시한다.
- **JSON 가져오기**: 1MB 이하 파일의 종류·버전·항목 수·문자열·레이아웃 프로파일을 먼저 검증한 뒤 기존 프리셋과 병합한다. 장비 값은 중복을 제거하고, 같은 스타일·이름의 레이아웃이 동일하면 건너뛰며 내용이 다르면 `이름 (2)`처럼 이름을 바꾸어 둘 다 보존한다. 검증에 실패하면 기존 프리셋은 바꾸지 않는다.
- **선택 사항인 디자인 프리셋**: 별도 접이식 패널에서 현재 디자인을 이름 붙여 localStorage `frame.appearances`에 저장·적용·삭제한다. 같은 이름을 저장하면 교체 확인을 받는다. 기존 장비·레이아웃 팔레트와 독립적이다.
- 디자인은 모든 스타일의 세로/가로 레이아웃, 현재 스타일, 영문/한글 글꼴 선택, 서명·로고 선택, 프레임색·구버전 톤 유지 상태, 전역 표시 여부·설정 항목 표시·날짜 형식, 비율·패딩색·크기·형식·품질을 포함한다. **카메라/렌즈/필름/날짜/설정/메모 값, 파일 제목, 사진, 장별 오버라이드, 장비 팔레트는 제외**한다.
- 화면에서 제거된 패딩색·긴 변 크기와 이전 자동 비율도 호환용 값으로 저장·복원한다. 기존 디자인을 적용하거나 다시 저장해도 해당 출력값을 초기화하지 않는다.
- 디자인 적용으로 달라진 레이아웃은 각 스타일의 기존 되돌리기에 기록한다. 디자인 전체의 별도 실행 취소는 없다.
- 디자인은 로컬 리소스의 선택 ID만 기억하며 글꼴·로고 바이트를 복제하지 않는다. 사용할 수 없는 리소스는 안내하고 다시 불러올 수 있다. 기존 장비·레이아웃 JSON 파일의 형식과 범위는 그대로 유지한다.

## 설계 결정

- **조합 프리셋 → 항목별 팔레트 전환** (2026-07, 사용자 결정) — 조합 저장은 "이름 짓기" 비용이 들고, 조합 수는 항목 수의 곱으로 늘어난다. 항목별 저장이면 이름도 필요 없고 `prompt()`도 사라진다.
- 장비 팔레트는 촬영 값만, 레이아웃 팔레트는 배치만 다룬다. 선택 사항인 디자인 프리셋이 전체 모양의 재사용을 담당하며 전역 촬영 값이나 장별 수동값을 덮어쓰지 않는다.
- **가져오기는 병합** — 다른 기기의 목록을 옮기다가 현재 팔레트를 잃지 않도록 전체 교체나 묶음 설정 복원을 하지 않는다.

## 알려진 한계

- 긴 프리셋 이름은 말줄임 처리하며 전체 이름은 버튼의 접근성 이름과 툴팁으로 확인할 수 있다.
- 가져오기는 파일 전체를 한 번에 병합하며 항목별 미리보기·선택은 없다.
- 디자인 프리셋은 이 브라우저에서 재사용하며 기존 프리셋 JSON에는 포함하지 않는다. 사진 원본 없이 활성 로고·파일 글꼴까지 포함하는 기기 간 작업 이동은 프로젝트 파일을 사용한다.

- [x] 팔레트 값이 자동완성 후보에 나타난다
