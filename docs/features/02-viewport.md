# 02. 줌/팬 뷰포트

## 목적

합성 결과를 라이트테이블 위에서 확인한다. 전체 구도(화면 맞춤)와 디테일(1:1로 엣지 프린트 확인)을 오가며, 촬영 정보를 타이핑하는 동안에도 보고 있던 위치를 잃지 않아야 한다.

## 현재 동작

CSS `transform: translate(x,y) scale(s)` 기반. 상태는 `zoom { scale, fit, x, y, mode }`.

- **미리보기 상단**: PhotoFrame·사진 추가·개인 설정만 화면 폭과 관계없이 한 행으로 배치한다. 미리보기와 같은 배경에서 구분선 없이 이어지고 소개 문구는 없다.
- **Structural Modernism UI shell**: 따뜻한 미색 workspace와 흰 설정 surface를 3px 구조선으로 구분한다. `1100px` 이상은 미리보기 + 우측 설정 rail의 2열, 그 미만은 한 열이며 `720px` 미만은 form row도 한 열로 쌓는다. 사진이 있으면 미리보기만 상단에 고정해 설정을 스크롤하며 결과를 계속 확인한다. 높이는 `clamp(240px,48dvh,520px)`, 헤더·스트립·설정은 페이지 흐름을 유지하며 빈 상태의 안내문은 기존 화면 높이를 사용한다.
- **화이트 / 블랙 테마**: 우상단 톱니바퀴 → 화면 테마에서 전환한다. 블랙은 무채색 UI만 어둡게 바꾸며 코발트 강조색·사진·합성 결과를 유지한다. 기본은 화이트이고 선택값은 기존 `frame.ui` 설정과 병합해 이 브라우저에 기억한다.
- **좁은 설정 패널**: 화면 폭과 별도로 rail의 실제 내부 너비가 280px 이하이면 입력을 한 열, 프레임 스타일을 2열로 바꾼다. 개인 설정의 패널 축소·UI 확대 조합에서도 필수 버튼을 유지한다.
- **모드 2개**: `fit`(화면 맞춤 유지) / `free`(사용자가 줌·팬한 상태). 뷰포트 리사이즈 시 `fit` 모드만 ResizeObserver로 재맞춤.
- **화면 맞춤 배율**: 뷰포트 높이에서 실제 줌바 높이와 32px 간격을 뺀 공간을 사용한다. `min((폭−48)/캔버스폭, (남은높이−24)/캔버스높이, 1)`로 계산하고 그 공간 중앙에 배치하므로, 2행 줌바에서도 사진이 도구막대에 가려지지 않는다. 계산 가능한 공간은 최소 1px이며 원본보다 확대하지 않는다.
- **휠 줌**: 커서 위치 고정점 유지, 배율 1.12/스텝. 범위 0.03×~4×.
- **핀치 줌·팬**: 미리보기 안에서 두 손가락 사이 거리로 확대·축소하고, 중점을 움직여 팬한다. 중점 아래 사진 지점을 유지하며 범위는 휠과 같은 0.03×~4×다. 두 번째 손가락이 닿으면 아직 끝내지 않은 요소·경계 이동은 시작 위치로 돌아간다. 한 손가락만 남아도 요소 이동을 재개하지 않으며 새 터치부터 한 손가락 조작을 시작한다.
- **드래그 팬**: pointer 이벤트 + `setPointerCapture`. 줌바·드롭존 위에서는 시작 안 함.
- **툴바**: − / 배율%(클릭=맞춤) / ＋ / 맞춤 / 1:1 / **경계** / **↶ 배치 되돌리기**. 버튼은 최소 48px이고 버튼 줌은 1.25/스텝, 뷰포트 중앙 고정점이다. `720px` 미만에서는 기능을 숨기지 않고 4열 × 2행으로 배치한다.
- **경계 토글 + 드래그 배치**: 미리보기 위에 카메라/렌즈/필름·기타/설정/날짜/메모/로고·서명의 실제 렌더 영역을 cobalt 점선 박스 + 라벨로 표시하고, **박스를 잡아 끌면 위치가 바뀐다**. 넘침은 빨간 박스와 안내 문구로 구분한다. 드래그 중 다른 요소의 경계·중앙이나 캔버스 중앙과 수평/수직이 맞으면 cobalt 가이드라인이 뜨며 스냅. 더블클릭으로 해당 요소 위치 초기화. 오프셋은 사진 폭 W 비율로 스타일·방향별 프로파일(각 요소 `DX/DY`)에 저장 — 해상도가 달라도 같은 자리이며 다른 프레임 스타일이나 사진 방향에 섞이지 않는다. 경계가 켜져 있으면 조정 부위 드래그는 배치·크기, 빈 곳 드래그는 팬. 가로 인스탁스 미니는 스택·회전 글씨 모두 개별 드래그를 지원한다. 세로 필름 스트립의 회전 엣지 프린트는 하나의 자동 배치 영역으로 표시되고 개별 드래그는 지원하지 않는다. render()가 `info.collect`일 때 요소 박스를 수집(`info.boxes`)하고 미리보기에만 오버레이 — 내보내기에는 포함되지 않는다. **기본 켜짐** — 줌바 '경계'로 끌 수 있고 선택은 `frame.ui`에 저장.
- **프레임 크기 핸들**: 정보 영역 크기는 스타일에 따라 아래·위·우측 경계선, 인스탁스·매트 계열의 사진 둘레 여백은 **사진 우상단 모서리의 사각 그립**으로 조절한다. 인스탁스 미니의 가로 사진만 정보 영역이 우측이며 스퀘어·와이드는 항상 아래쪽이다. 그립을 왼쪽·아래(SW)로 끌면 여백이 커지고 오른쪽·위(NE)로 끌면 작아진다. 변화량은 드래그 시작 시 화면 배율과 포인터 이동 거리로 계산해, 합성 크기가 바뀌어 화면 맞춤이 다시 실행되어도 같은 포인터 위치에서 값이 출렁이지 않는다. 드래그 중 파란 강조 + 현재 % 라벨, 1% 단위, fit 모드에서는 1400px 축소본으로 렌더한다. 설정의 `사진 둘레 여백 %` 슬라이더·숫자 입력으로도 같은 값을 조절한다.
- **다단계 배치 되돌리기**: 요소 이동, 프레임 크기 변경, 레이아웃 수치 변경, 프리셋 적용, 더블클릭·버튼 초기화 직전의 현재 스타일 세로·가로 프로파일 한 쌍을 세션 메모리에 최대 50개 보관한다. `↶ 배치 되돌리기 (N)`을 반복해서 누르면 현재 프레임 스타일의 조작을 최근 순서부터 복원한다. 사진 삭제는 되돌리기 대상에 포함하지 않는다. 스타일별 기록은 독립적이며 프로젝트를 열거나 새로고침하면 임시 기록을 지운다.
- **정밀 이동**: 표시·레이아웃 설정에서 현재 사진에 표시된 개별 요소를 고르고 ← ↑ ↓ → 버튼으로 사진 폭의 0.1%·0.5%·1%씩 이동한다. 현재 미리보기 사진 방향의 프로파일에 저장하며, 선택 요소 초기화와 기존 배치 되돌리기를 지원한다. 경계 박스를 눌러도 대상 요소가 선택된다. 숨긴 요소와 세로 필름의 자동 회전 영역은 정밀 이동 대상에서 제외한다. 정확한 이동량을 유지하므로 결과물 밖으로 이동하면 기존 넘침 경고가 표시된다.
- **호버 피드백**: 조정 가능한 부위 위에 마우스를 올리면 해당 핸들·박스가 파랗게 강조되고 커서가 바뀐다(박스 `move`, 모서리 그립 `nesw-resize`, 선 `ns/ew-resize`). 히트 우선순위는 호버와 클릭이 동일 — 모서리 그립 → 경계선 → 요소 박스 → 팬.
- **키보드**: `+ − 0 1` (input/select/textarea 포커스 중에는 무시).
- **좁은 화면 이동**: 아래로 스크롤해 설정 레일에 접근하고 `↑ 미리보기로`로 미리보기 시작점에 돌아온다. 사진이 있을 때 레일의 이동 버튼은 고정 미리보기와 겹치지 않게 일반 페이지 흐름에 둔다.
- **줌 유지 규칙**: 정보 입력 → `refresh(true)`로 free 줌 유지. 스타일 변경 → 비율이 바뀌므로 맞춤 리셋. 사진 선택 변경 → `refresh(true)` (같은 롤이면 비율이 대체로 같으므로 유지).
- **UI와 결과물 분리**: shell 색·선·breakpoint와 줌바 배치는 CSS UI에만 적용한다. 합성 색과 사진 폭 `W` 기준 수치는 `C`, `render()`, 스타일·방향별 profile에 그대로 남으며, 미리보기와 내보내기는 같은 렌더 경로를 계속 공유한다.

## 설계 결정

- **canvas 재렌더 + transform 분리** — 줌·팬은 transform만 바꾸므로 픽셀 재합성 없이 즉각적. 재합성은 정보가 바뀔 때만.
- **커서 고정점 수식**: 고정점이 가리키는 캔버스 좌표 `(px−x)/s`를 새 배율에서도 같은 화면 위치에 유지. 표준 기법이지만 fit/free 모드 구분과 결합한 것이 이 도구의 요점 — "사용자가 만진 줌은 존중, 아니면 항상 전체 보기".
- 최소 배율 0.03×: 매우 큰 스캔(1만px대)도 화면 맞춤이 가능해야 해서.

## 알려진 한계

- 핀치·정밀 이동 동작은 `node tools/check-mobile.mjs`로 회귀 검사한다. 실제 모바일 기기의 손가락 입력·화면 키보드는 별도 실기기 검증이 필요하다.
- transform scale 확대 시 캔버스가 블러 처리됨(브라우저 보간) — 1:1 이상 확대는 픽셀 확인용으로는 부정확.
