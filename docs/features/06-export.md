# 06. 내보내기 + 파일 시스템

## 목적

사진 묶음을 한 번에, 지정한 폴더로, 공유하기 좋은 크기로 저장한다. 여러 파일을 다운로드 목록에서 다시 정리하는 경험을 줄이는 것이 목적이다.

## 현재 동작

- **비율 맞춤**: Instagram 사진 피드 자동(기본) / 원본 / 3:4 / 4:5 / 1:1 / 1.91:1 / 9:16 스토리 + 여백 색(흰색/아이보리/검정). 자동은 3:4~1.91:1 밖의 결과만 `padToRatio()`로 중앙 패딩한다. 미리보기와 내보내기는 같은 옵션을 사용하고 캔버스 한계 계산에도 반영한다.
- **크기**: 긴 변 2048px(인스타 권장) / 1440px / 원본. 패딩 후 `downscale()`에서 초과분만 축소.
- **포맷**: PNG(기본, 무손실) / JPEG + 품질 50~100(기본 92). JPEG 선택 시에만 품질 필드 표시. 확장자(.png/.jpg)가 형식을 따라간다.
- **저장 위치**:
  - `showDirectoryPicker({ mode:'readwrite' })` 지원 시(Chromium) "저장 폴더 선택" → 이후 모든 내보내기가 그 폴더로 직행.
  - API가 없거나 사용할 수 없으면 버튼 비활성 + 경고 표시, `<a download>` 다운로드 폴백. 장당 350ms 딜레이로 브라우저 다운로드 연타 차단을 완화한다.
- **파일명**: 파일 제목을 입력하면 필름 스트립 순서대로 `제목(1), 제목(2)…{확장자}` (예 `강릉여행(3).jpg`) — 한 장만 내보내도 전체 순서 기준 번호가 붙는다. Windows 금지 문자(`\/:*?"<>|`)는 자동 제거. 제목이 비어 있으면 `원본이름_framed.{확장자}` 폴백.
- **충돌 방지**: 선택한 폴더에 같은 이름이 있으면 기존 파일을 덮어쓰지 않고 확장자 앞에 ` (2)`, ` (3)`을 붙인다. 예를 들어 `강릉여행(1).jpg`가 있으면 `강릉여행(1) (2).jpg`로 저장해 사진 순번은 유지한다. 다운로드 폴백의 중복 이름은 브라우저가 처리한다.
- **범위**: 전체 내보내기 / 현재 장만 내보내기.
- **진행·결과 상태**: 진행 막대와 `현재/전체 · 파일명`을 표시하고 내보내기 중에는 내보내기·프로젝트·프리셋·폴더 버튼을 잠근다. 폴더 쓰기는 저장·실패·자동 축소·이름 변경 수를 요약한다. 다운로드 폴백은 브라우저의 실제 저장 완료를 알 수 없으므로 `N장 다운로드 요청`이라 쓰고 다운로드 목록 확인을 안내한다. 한 장의 렌더·인코딩·저장이 실패해도 나머지는 계속하며, 폴더 권한이 끊기면 남은 작업을 중단하고 폴더 재선택을 안내한다.

### Instagram 근거와 범위

- 2025년 5월 [Instagram Creators 공식 채널](https://www.instagram.com/channel/AbblUjTFQ69pvy6a/AbZvyCPrUB0795Wn/)은 원본 3:4 사진 지원과 기존 1:1·4:5 선택 유지를 공지했다. 이를 근거로 3:4 고정 옵션과 자동 모드의 세로 하한을 3:4로 바꿨다.
- 해당 공지는 Instagram 앱 사진 게시에 관한 내용이다. 예약 게시·광고·타 서비스 연동까지 같은 규격이라고 추정하지 않으며 UI에 게시 경로별 차이를 확인하라고 표시한다. 1.91:1은 기존 PhotoFrame의 가로 옵션과 자동 상한을 유지한 것이며 이번 변경에서 최신 공식 공개 문서로 재확인하지 못했다.

## 설계 결정

- **File System Access API 우선** — 사진 묶음 흐름의 완성. 폴더 핸들은 세션 동안만 유지(권한 모델상 재선택 필요).
- **제목 + 순번 명명** — 한 묶음을 한 주제로 올리는 흐름(예: 강릉여행)에서 스트립에서 정한 순서가 곧 파일 순서가 된다. 제목이 없으면 원본 이름 + `_framed` 접미사로 스캔 파일과의 대응을 유지.
- **PNG 기본** — 텍스트·퍼포레이션의 선명도를 보존한다. 용량이 중요한 묶음은 JPEG 품질 옵션을 쓸 수 있다.
- **오류가 전체 묶음을 지우지 않게** — 장당 오류를 별도로 수집하고, 쓰기 실패 시 스트림을 중단해 완료되지 않은 파일을 정상 결과로 보고하지 않는다.

## 알려진 한계

- 다운로드 폴백에서 여러 장 저장 시 브라우저가 "여러 파일 다운로드" 허용을 물을 수 있다.
- 다운로드 폴백은 다운로드 요청 이후 사용자의 취소·브라우저 차단·실제 디스크 저장 성공을 감지할 수 없다.
- 진행 중 사용자가 취소하는 버튼은 없다.
- 완료 요약에는 실패한 원본명을 최대 3개만 표시한다.

## 수용 기준

- [x] File System Access API가 있으면 폴더 지정 후 클릭 한 번으로 전체를 저장한다
- [x] 폴더 API를 쓸 수 없으면 다운로드 폴백으로 요청하고 완료 여부를 구분해 표시한다
- [x] 파일명에서 원본 파일과의 대응을 알 수 있다
- [x] JPEG 품질을 선택해 내보낼 수 있다
- [x] 내보내기 형식에 맞는 확장자가 붙는다
- [x] 같은 이름의 기존 파일을 덮어쓰지 않는다
- [x] 여러 장 내보내기 중 현재 파일·진행률을 보고 완료·실패 개수를 확인할 수 있다
